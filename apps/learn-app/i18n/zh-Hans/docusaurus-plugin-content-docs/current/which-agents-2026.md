## 找到你的起点

选择你的第一位 AI 员工，最简单的方法就是回答四个问题：你希望主要在哪里工作，是终端、桌面应用，还是消息应用？你希望它有多强的自主性，是与你协作，还是自行运行任务？你的数据主要存放在哪里，是本地文件、企业系统，还是聊天工作流？以及，你对安全性的要求到底有多严格？这四个问题一旦想清楚，选择就会容易得多。

你不需要在第一天就用上全部五种工具。先在下表找到自己，然后从那里开始。

| 你是…… | 从这里开始 | 原因 |
| ----------------------------------------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **构建软件的开发者或工程师** | **Claude Code** + **OpenClaw** | Claude Code 是你的全能型 AI 员工，直接在你的电脑上工作。OpenClaw 则把个人 AI 助手带到你的手机和消息应用里。 |
| **金融、法律、运营或其他领域的专家** | **Claude Cowork** + **OpenClaw** | Cowork 负责你的业务工作流，比如报告、分析和文档处理，而且不需要任何技术配置。OpenClaw 则通过 WhatsApp 或 Slack 帮你处理日常任务。 |
| **正在推动 AI 落地的高管或团队负责人** | **Claude Cowork** | Cowork 能连接你团队现有的工具（Google Drive、Gmail、Excel、DocuSign），并自动运行定时任务。从这里开始，你最容易真实感受到 AI 员工到底是什么体验。 |
| **设计 AI 驱动系统的产品经理或架构师** | **Claude Code** + **Codex** | Claude Code 适合通用工作和原型验证；当你需要针对复杂系统设计进行高强度推理时，再调用 Codex。 |
| **极度重视安全与数据控制的人** | **Cowork、Claude Code、NanoClaw** | NanoClaw 会让每个 AI 员工都运行在你机器上的封闭容器中，没有任何东西会意外泄露。它的代码库也足够小，你可以自己通读并审计。 |

## 第一天该装什么

**如果你是开发者：** 安装 [OpenClaw](https://openclaw.ai) 和 [Claude Code](https://claude.com/code)。从第一部分开始，你就会同时用到它们。

**如果你不是开发者：** 安装 [OpenClaw](https://openclaw.ai) 和 [Claude Cowork](https://claude.com/cowork)（位于 Claude Desktop 内）。不需要命令行。

## 你的智能体组合成本

运行一组 AI 员工，意味着你需要管理 API 与订阅成本。大致可以这样预估：

*   **OpenClaw 与 NanoClaw（免费 + API 成本）：** 这两款软件都完全开源（MIT 许可证）。但由于它们虽然本地运行，却在云端完成推理，所以你需要按 token 向 [Anthropic](https://platform.claude.com/docs/en/about-claude/pricing)、[OpenAI](https://openai.com/api/pricing/) 或 [DeepSeek](https://api-docs.deepseek.com/quick_start/pricing) 支付 API 费用。若为高频日常使用，通常每月会花费 **$15 到 $40** 的 API 额度。
*   **Claude Code（免费 + 订阅）：** CLI 工具本身免费，但至少需要订阅 [Pro Plan](https://claude.com/pricing)，最低为 **$20/用户/月**。如何降低这部分成本，可参见第 3 章。
*   **Claude Cowork（订阅制）：** Cowork 包含在 [Anthropic 的高阶套餐](https://claude.com/pricing) 中（通常是 Pro、Max 或 Enterprise，起步价约 **$20/用户/月**，最高可到 **$200/用户/月**）。它提供对桌面文件的深度访问，且不按 token 单独计费。**订阅这些套餐后，你通常可以同时使用 Claude Code 和 Claude Cowork。** 降本方法同样可参考第 3 章。
*   **Codex / GPT-5.4-Codex（订阅/API）：** OpenAI 的云模式工程环境需要 [高阶 OpenAI 订阅](https://developers.openai.com/codex/pricing/) 或较重的 API 使用量，而成本会随着你的系统架构任务复杂度上升。

## 通用智能体

### Cowork - 你的企业级 AI 员工

Cowork 是 Anthropic 面向非终端用户业务专业人士打造的 AI 员工。它运行在 macOS 和 Windows 上的 Claude Desktop 应用内部。

**你可以把它理解为：** 一位见多识广的同事，帮你接手那些你总没时间做完的工作，比如制作报告、分析文档、整理文件、起草演示文稿，以及管理重复性任务。它可以直接连接到团队的日常工具，包括 Google Drive、Gmail、Google Calendar、DocuSign、Excel、PowerPoint 等等。连接器的可用性提升得很快，但在实际使用中，仍然取决于你的套餐、管理员配置，以及你所在组织启用了哪些插件。与其把 Cowork 看成一个固定功能的应用，不如把它理解为一个企业级 AI 工作面板，它的价值会随着团队真正接入的系统而不断增加。

2026 年 2 月，Anthropic 发布了一次重要的企业级升级：私有插件市场（也就是由你的公司精确控制哪些能力可以使用）、面向 HR、财务、工程、法务和运营的部门专属插件，以及一个 `/schedule` 命令，让你配置自动运行的任务，比如每周一早晨自动执行一次竞争对手分析。

_第三部分覆盖业务领域工作流，包括财务、法务、市场和运营，这正是 Cowork 最擅长处理的工作。_

---

### Claude Code - 你的全能型通用智能体

Claude Code 由 Anthropic 构建，运行在你的电脑上。尽管名字里有“Code”，但它做的远不止写代码。Anthropic 把其底层框架从 “Claude Code SDK” 更名为 **Claude Agent SDK**，因为团队已经在用它做研究、视频制作、数据分析、笔记整理，以及数十种非编码任务。

**你可以把它理解为：** 一个通用智能体，它能做几乎任何你能在电脑上完成的事情，只是速度更快。你只需要用自然语言交待任务，比如分析这张表格、整理这些文件、研究这个主题、实现这个功能，它就会自己规划步骤、执行工作，并把结果展示给你。它能读取文件、运行命令、管理代码，甚至还能把子任务分派给并行工作的专门助手。

Claude Code 是你在本书中使用最多的主工具。它的技能系统（名为 SKILL.md 的可复用指令文件）以及它生成专门子员工的能力，共同构成了 Agent Factory 方法的基础积木。

_第 5 章会以 Claude Code 为引擎，引入 Spec-Driven Development。你将在本书每个部分都用到它。_

---

### Codex - 你的强力工程 AI 员工

Codex 是 OpenAI 面向高难工程问题打造的通用 AI 智能体。它有两种模式：一种是云模式，在隔离环境里完全自主工作（通常每个任务耗时 1 到 30 分钟）；另一种是运行在你本机上的命令行工具。

**你可以把它理解为：** 遇到最难任务时才会请出的专家。Claude Code 负责日常，而 Codex 则是为复杂推理而造，尤其适合那些需要深度思考的系统架构设计。它的最新模型（GPT-5.3-Codex）把前沿级编码能力与高级推理结合在一起，而且正在从代码领域扩展到更广泛的知识工作。

在云模式下，你只需描述自己想要什么，Codex 就会自主规划、构建、测试并反复迭代，直到结果通过你的测试，整个过程都在封闭沙箱中完成。你还可以并行运行多个任务，每个任务都在自己的隔离环境内执行。

当任务工程属性强、边界清晰且可测试时，就该使用 Codex：例如大型重构、迁移、架构探索、跨大型代码仓库调试，或者那些适合在隔离环境中并行推进的实现工作。它适合那种需要一个智能体完整跑通一项重要软件任务，而不仅仅是在单个文件里做自动补全的场景。

## 个人 AI 员工

### OpenClaw - 你的个人 AI 员工

OpenClaw 由 Peter Steinberger 创建，并获得 **OpenAI** 与 **Vercel** 支持。到 2026 年初，它已经成为 GitHub 上获得星标最多的软件项目，在大约 120 天内就突破了 25 万星。

**你可以把它理解为：** 一个不知疲倦的个人助理，直接连接你的消息应用。它可以帮你整理邮件、管理日历、预订航班、处理保险文件，以及执行你教给它的各种日常任务，全部通过 WhatsApp、Telegram、Slack，或你已经在使用的 50 多种消息应用来完成。

OpenClaw 完全开源（MIT 许可证）。你在自己的机器上运行它，自由选择 AI 模型（Claude、GPT、DeepSeek 或其他模型），并通过 ClawHub 市场中 5700 多个社区构建技能来扩展它。它的个性由一个简单的 Markdown 文件 SOUL.md 配置，而这正是你将在本书中学习编写规格时接触到的同一种格式。

_第 7 章会带你使用 OpenClaw 搭建你的第一位 AI 员工。_

---

### NanoClaw - 你的安全型 AI 员工

[NanoClaw](https://github.com/qwibitai/nanoclaw) 是 OpenClaw 的轻量级、安全优先替代方案。OpenClaw 的代码接近 50 万行，而 NanoClaw 用一个足够小、足够易读易懂的代码库，提供了同样核心的体验，也就是在消息应用中的 AI 助手。

**你可以把它理解为：** 上了锁的 OpenClaw。每一位 AI 员工都在你机器上的独立封闭容器中运行，也就是一个被隔离的环境。除非你明确授权，否则它只能看到你允许它访问的文件，也不能访问互联网。这不是某个软件选项，而是由操作系统本身强制执行的（Linux 上是 Linux 容器，macOS 上是 Apple Containers）。

NanoClaw 可连接 WhatsApp、Telegram、Slack、Discord 和 Gmail。它拥有持久记忆、定时任务（每日简报、每周报告、流水线监控），也是第一个支持 **agent swarms** 的个人 AI 助手，也就是能在你的聊天空间中协作的专门 AI 员工团队。它直接运行在 Anthropic 的 Agents SDK 之上，而这也正是你将在第 5 部分学习构建的同一套框架。

_第 5 部分会教你使用驱动 NanoClaw 的同一框架来构建定制 AI 员工。_

## 安全与隐私深度解析（尤其适合 NanoClaw 用户）

在 2026 年，安全仍然是头等关切。NanoClaw 的封闭容器方案（未经明确授权不得向外发送流量）使它成为处理知识产权敏感工作时最安全的选择，你甚至可以亲自审计这套约 3000 行的代码库。OpenClaw 提供了本地运行的灵活性，但默认仍依赖云模型（如果想完全不上云，可以使用本地版 DeepSeek）。Claude Cowork 与 Claude Code 运行在 Anthropic 的安全环境中，并带有企业级控制能力（私有插件、审计日志），但不会把原始源内容直接暴露给提供方。对于受到强监管约束的团队（例如金融、医疗），可以把 NanoClaw 与物理隔离模型搭配使用。

## 权衡与真实性能说明

没有哪一个智能体能在所有场景中获胜。以下是基于 2026 年初用户报告和内部基准得出的简要权衡：
- Claude Code 在交互速度和逐步推理方面领先，在多文件重构任务中通常能获得高出 20% 到 40% 的成功率，但在一次性任务里有时会显得“话有点多”。
- Codex（GPT-5.3-Codex）在云模式下特别擅长长链路规划和并行子任务处理，在复杂架构任务中 token 效率最高可提升 5 倍，但本地 CLI 模式在延迟上仍落后于 Claude Code。
- OpenClaw 在持续在线的个人自动化方面非常出色（5700+ 个社区技能），但若想达到 Claude Code 开箱即用的可靠性，通常需要更多提示工程。
- NanoClaw 用部分速度换取了近乎钢板级的安全性（封闭模式下不会发生意外网络调用），因此成为受监管行业的首选。
- Cowork 在非技术型工作流中占据优势（例如 Excel + Gmail + /schedule 自动化），但并不具备 Claude Code 或 Codex 那样深入的代码理解能力。

实际成本会随使用方式变化：重度使用的 Claude Code 组合平均每月大约 $25 到 $60；如果把基于 DeepSeek 的 OpenClaw 混合进来，则可能降到 $10 到 $25。你应该亲自测试失败模式，大多数用户会并行运行两套 A/B 组合 2 到 4 周再做决定。

## 全局视角：你的智能体组合

没有人只使用一位 AI 员工。到 2026 年，最有效的配置是一套组合：通用智能体负责你的日常工作，个人 AI 员工则在消息应用和业务工作流中自主运行。

组合并不意味着你每天都要用到每一款工具。实际情况通常是，大多数人会有一个日常主力和一个专门角色：例如 Claude Code 加 OpenClaw，或者 Cowork 加 NanoClaw，或者 Claude Code 加 Codex。目标不是收集工具，而是实现覆盖：一位智能体负责你的默认工作流，另一位负责你的默认工具并不擅长的任务。

通用智能体是你拿来 *使用* 的；个人 AI 员工是你拿来 *构建并部署* 的，而且最终还是可以 *出售* 的。本书会同时教你这两件事：一方面，今天就把 Claude Code、Cowork 和 Codex 的杠杆效应发挥到最大；另一方面，利用 OpenClaw 和 NanoClaw 构建属于你自己的、别人愿意付费使用的 Digital FTE。

## 迁移与组合演进

你的智能体组合会不断演进：先从小处开始，再逐层叠加。一个常见路径是：第 1 天 = OpenClaw + Claude Code/Cowork -> 第 3 个月 = 针对高难工程任务加入 Codex -> 第 6 个月 = 为敏感任务引入 NanoClaw，或通过 SKILL.md/SOUL.md 构建定制智能体。

迁移建议：在不同智能体之间导出/导入 SKILL.md 模式；把 ClawHub 的社区技能当作过渡桥梁；每周监控 token 消耗（第 3 章会介绍优化脚本）。许多读者在组合使用 3 个以上智能体后，报告生产力提高了 2 到 3 倍，但要避免工具蔓延，除非你是在为客户构建方案，否则核心工具最好控制在 4 到 5 个以内。

---

## 超越核心组合：探索替代方案

虽然 Claude Code、Cowork 和 NanoClaw 已经构成了非常强的基础，但 2026 年的智能体生态远比这更丰富。像 Gemini CLI、Qwen Code、OpenAI Agents SDK 和 Claude Agents SDK 这样的开源框架，能够驱动复杂编排场景中的多智能体组合；当它们与 DeepSeek 或 Qwen 模型搭配时，成本往往还能更低。无代码/低代码构建器（Vellum、Microsoft Copilot Studio、Zapier Central、Salesforce Agentforce）则让非技术团队无需 SDK 或终端，就能更快部署智能体。

如果你是纯开放模型路线的支持者，那么基于 Llama 4、DeepSeek、Mistral 或 Gemma 构建的工具，还提供完全本地或自托管的选项，彻底摆脱云依赖。如果隐私比速度更重要，这会是理想选择。本书之所以聚焦 Claude Code 及其搭档，是因为它们目前能为绝大多数读者提供最高杠杆，但你最好每个季度都尝试一种替代方案，以便让自己的智能体组合具备面向未来的韧性。
