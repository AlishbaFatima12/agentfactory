### Core Concept
PRIMM-AI+ is not just five stages -- it embeds four proven teaching methods (worked examples, Parsons problems, live coding, and peer instruction) into a consistent five-step lesson architecture that repeats at both lesson and chapter scale. Every chapter in this book follows the same pattern: predict with worked examples, run and compare, investigate with artifacts, modify existing code, then make new programs from specifications.

### Key Mental Models
- **Worked Examples as Cognitive Load Reduction**: Studying complete programs before writing separates understanding *how* code works from inventing *what* to write, reducing mental burden.
- **Parsons Problems as Structural Tests**: Reordering scrambled code tests whether you understand not just what code does, but why the order matters (data flow, dependencies).
- **Classroom vs Solo Mode**: Classroom mode uses human collaboration for predictions and discussions; solo mode replaces that with structured AI interaction after AI-free checkpoints.
- **Five-Step Lesson Architecture**: Every lesson follows predict (worked example), run and compare, investigate (with artifacts and optional Parsons), modify, make (with specification) -- the pattern becomes automatic after two chapters.

### Key Facts
- **Four embedded teaching methods**: Worked examples (predict/investigate), Parsons problems (between investigate/modify), live coding (investigate/modify), peer instruction (all stages).
- **This book targets solo mode**: You, the book, and your AI assistant -- classroom teachers add collaborative elements on top of the same structure.
- **Parsons problem function**: Tests structural understanding by giving correct code lines in scrambled order; you reorder them to prove you understand data flow and dependencies.
- **Chapter-scale pattern**: Opening worked examples, investigative lessons, structural bridges (Parsons), modification exercises, make capstone.

### Critical Patterns
- Prediction-reality gap drives learning regardless of mode -- commit your prediction in writing before running code.
- You understand before you change, and you change before you create -- no stage is skippable.
- Parsons problems appear inside Investigate step when a lesson needs to verify structural understanding before free modifications.
- Confidence scoring is especially critical in solo mode because it makes self-deception visible without a classmate to challenge assumptions.
- Every lesson and every chapter follows the same rhythm -- once you recognize the pattern, you never feel lost.

### Common Mistakes
- Skipping the prediction step because you want to "just run it and see" -- bypasses the prediction-reality gap that drives learning.
- Treating worked examples as templates to copy instead of programs to understand -- misses the cognitive load reduction benefit.
- Confusing Parsons problems with fill-in-the-blank exercises -- Parsons test structural understanding (order, dependencies), not syntax recall.
- Assuming solo mode is weaker than classroom mode -- the AI-free checkpoints and confidence scoring provide the same accountability as a teacher or peer.
