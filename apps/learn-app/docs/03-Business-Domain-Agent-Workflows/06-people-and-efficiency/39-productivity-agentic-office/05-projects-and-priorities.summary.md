### Core Concept

Project amnesia — starting every project briefing from scratch, rediscovering risks, relitigating decisions — is the most expensive failure mode in professional work. Layer 3 holds the context that prevents it: codenames, current milestones, honest risk flags, and key decisions already made. The completeness of the layer determines the quality of every subsequent output that references it.

### Key Mental Models

- **Forced-choice priority**: If you have more than three P1 projects, you have not prioritised — you have listed. The rule is a discipline, not a limitation. Classifying a fourth project as P1 requires explicitly demoting one of the existing three.
- **Codenames as information management**: A codename serves three purposes — privacy (safe in mixed company), efficiency (shorter), and identity (a shared reference point for the team). "Project Nighthawk" in a mixed meeting is safer than "Karachi expansion."
- **Search gap as completeness signal**: When `/agentic-office:workplace-search` returns "not in workplace memory," that is useful information. Every gap is a prompt to add what is missing. The search makes your memory gaps visible.

### Critical Patterns

- Write project entries with ten fields: name, codename, status, priority, owner, description, current_milestone, next_milestone, at_risk, decisions
- Apply the at_risk field specifically: "Facility agreement stalled 10+ days — escalation needed" not "some scheduling challenges"
- Log at least one key decision per project — decisions not recorded will be relitigated
- Run `/agentic-office:workplace-search` after adding entries to verify what the system knows and identify gaps

### Common Mistakes

- Vague at_risk fields that cannot be acted on — if you cannot name the specific risk, write what you know and refine later
- Classifying more than three projects as P1 — this signals a planning problem, not a priority list
- Not logging decisions — the most common cause of rework is relitigating something already decided
