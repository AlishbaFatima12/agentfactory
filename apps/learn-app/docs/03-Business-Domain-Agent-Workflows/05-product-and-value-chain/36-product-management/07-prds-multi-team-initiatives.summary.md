## Summary: PRDs for Multi-Team Initiatives

- **Key concept**: A PRD and a feature spec answer different questions. The spec asks 'how do we build this feature?' The PRD asks 'should we make this bet, and what does winning look like?' Scope, audience, and commercial context distinguish them.
- **Command(s) used**: `/prd` (custom `product-strategy` plugin)
- **Artifact produced**: 10-section PRD for InsightFlow's Workflow Builder initiative — wrapping the L06 trigger configuration spec into the broader multi-team document with commercial evidence, MoSCoW-prioritised functional requirements, non-functional requirements, GTM plan, and failure threshold
- **Quality criteria**: Commercial evidence must be quantified with sources; no more than 60% of functional requirements labelled MUST; failure threshold defined before launch; engineering lead must confirm Section 6 before REVIEW status
- **Next lesson**: Lesson 8 decomposes this PRD's user requirements (Sections 3 and 4) into sprint-ready user stories using `/stories` from the custom product-strategy plugin
