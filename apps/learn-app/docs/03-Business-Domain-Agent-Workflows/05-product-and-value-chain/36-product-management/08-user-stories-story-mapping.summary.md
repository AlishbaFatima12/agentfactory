## Summary: User Stories & Story Mapping

- **Key concept**: User stories translate PRD requirements into sprint-ready slices using the three-part anatomy (persona / capability / user outcome). Each part has a quality rule that prevents the ambiguity that causes sprint failures.
- **Command(s) used**: `/stories` (custom `product-strategy` plugin)
- **Artifact produced**: Story backlog for InsightFlow's Workflow Builder trigger configuration: with stories for Analyst Alex (schedule trigger, threshold trigger) and VP Priya (email report action), covering all user flows from the L06 spec with error state ACs
- **Quality criteria**: Named persona (not "a user"), capability not UI element, user outcome not system action, at least one error state AC per story, stories under 7 ACs (split if over)
- **Next lesson**: Lesson 9 uses this story backlog to build InsightFlow's Q3 roadmap with /roadmap-update (official plugin), organising stories into Now/Next/Later format for three audiences. Lesson 10 RICE-scores the same backlog to prioritise the first sprint.
