## Summary: Feature Specifications

- **Key concept**: A feature spec lives between the vague spec (under-specified, engineers make product decisions) and the over-specified spec (over-specified, PM makes engineering decisions). The five-section anatomy and four AC rules define the craft middle ground.
- **Command(s) used**: `/write-spec` (official `product-management` plugin)
- **Artifact produced**: Five-section feature spec for InsightFlow's custom metric alerts feature — with explicit IN/OUT OF SCOPE list, numbered testable acceptance criteria, edge case table, and open questions with owners
- **Quality criteria**: Every acceptance criterion must be independently testable, contain no "and," specify behavior not implementation, and use measurable thresholds for performance requirements
