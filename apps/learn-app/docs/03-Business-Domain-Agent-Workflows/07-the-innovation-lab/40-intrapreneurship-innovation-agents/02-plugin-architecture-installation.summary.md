# Lesson 2: Plugin Architecture and Installation: Summary

## What You Learned

The innovation plugin gives you 10 commands mapped across all three DLA stages: `/discovery` and `/idea` for Design Thinking, `/hypothesis` and `/validate` for Lean Startup, `/sprint` for Agile, and four cross-cutting tools (`/market`, `/financials`, `/pitch`, `/gtm`) that apply at any stage. Every command is stage-aware ; it checks your venture stage and warns if you are asking for work you are not ready for.

The `innov.local.md` file is the configuration layer that transforms generic outputs into venture-specific ones. Without it, commands produce generic frameworks. With it, they work with your actual customers, assumptions, and traction data. You copied the template this lesson; you will fill it in progressively through Lessons 3–14 and complete it in the Lesson 15 capstone.

## Key Takeaways

- The 10 commands map directly to DLA stages, understanding this helps you select the right command at the right time
- Stage-aware calibration prevents you from running financial models before you have customer data, or generating ideas when you already have a validated product
- `innov.local.md` works alongside `work.local.md` from Chapter 28; it is an extension, not a replacement
- Fill in the `venture:` section now; even a rough problem statement changes output quality immediately
- You install skills and agents only , not the repository's development artifacts (evals, tests, examples)
