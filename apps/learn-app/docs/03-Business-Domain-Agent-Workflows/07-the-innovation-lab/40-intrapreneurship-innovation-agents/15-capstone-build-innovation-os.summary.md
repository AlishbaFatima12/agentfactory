# Lesson 15 Summary: Capstone — Build Your Innovation OS

## What you learned

This lesson is integration, not instruction. You assembled everything from the prior 14 lessons into a single coherent file — `innov.local.md` — the venture context that makes every plugin skill and persistent agent specific to your venture. Without this file, the Innovation OS is a set of general-purpose tools. With it, every tool becomes a venture-specific intelligence system.

## Key takeaways

- **innov.local.md is the integration point of the entire chapter.** Every prior exercise produced data that feeds one of its six sections: customer profiles from L03, selected idea from L04, assumption stack from L05–L07, BMC from L08, unit economics from L09, competitive landscape from L10, GTM ICP from L11, and pitch data from L12.
- **The 4-question validation test is the quality gate.** Run all four prompts. If any response is generic, find the section causing it and add specificity. Generic output from `/idea` signals vague customer_profiles. Generic output from `/pitch` signals insufficient financial data or placeholder fundraising section.
- **The four most common gaps reveal the hardest parts of the venture.** Customer pains that are vague, fewer than 10 assumptions, generic differentiation, and all-ASSUMED financial models all indicate that the venture has not yet done the hard discovery and validation work the prior lessons teach.
- **innov.local.md is a living document, not a one-time setup.** Update it after every significant learning. The version number tracks how your understanding of the venture has evolved. A stale file produces stale intelligence.
- **For intrapreneurs, the intrapreneurship section replaces fundraising.** The approval pathway, stakeholder map, and success definition are your innovation committee equivalent of an investor pitch and pipeline.
