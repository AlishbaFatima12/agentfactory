# Ch 23: Sales/RevOps/Marketing — Prompt & Context Architecture Fix

## Problem

Ch 23 prompts are broken because they:

1. Research fictional entities (NexaFlow, Meridian Logistics, Sarah Chen) via web search → get nothing useful
2. Show fabricated "expected output" that can never appear in real Cowork sessions
3. Have no persistent grounding — each prompt floats without data context

## Root Cause

Prompts were written assuming Cowork has memory or web access to fictional companies.
In reality, Cowork has: local file access, folder instructions, session context, and web search (which finds nothing for fictional entities).

## Solution: Three-Layer Persistent Context Architecture

### Layer 1: Folder Instructions (always on)

Set once in L01 via Cowork sidebar → Instructions. Contains:

- Company identity (NexaFlow SaaS Analytics)
- ICP summary
- Data file references
- Brand voice essentials

### Layer 2: Generated Files (on disk)

- `demo-data.md` — 20 closed-won deals, 5 prospects, 10 pipeline deals, campaign history, competitor intel
- `sales-marketing.local.md` — ICP and brand voice config
- Both generated by student in L01, available to all subsequent lessons

### Layer 3: Session Context (within lesson)

- Each prompt builds on previous outputs in same session
- No need to re-reference files after first load in session
